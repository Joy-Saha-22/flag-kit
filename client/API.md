API AS BUILT (dashboard)
Every request: credentials "include". Every non-GET request must send the header X-Requested-By: flagkit-dashboard (otherwise the server answers 403). JSON bodies. Errors always look like { error: { code, message, requestId, details? } }; details is [{ in, path, message }] for validation_failed. 401 means not signed in. 429 (code rate_limited) has a Retry-After header in seconds.
Roles per project: viewer reads; editor also creates and changes flags and environment configs, and lists SDK keys and the audit log; admin also deletes flags and creates or revokes SDK keys.
- POST /api/auth/register {email, password (12 to 72 bytes), name} -> 201 {user:{id,email,name}}; 409 conflict. POST /api/auth/login {email,password} -> {user}; 401 invalid_credentials (same for an unknown email). POST /api/auth/logout -> 204. GET /api/auth/me -> {user}.
- GET /api/projects -> {projects:[{id,name,key,role,createdAt}]}. POST /api/projects {name,key} -> 201 {project:{id,name,key,role},environments:[{id,key,name}]}; 409 conflict; 403 limit_reached. Keys match ^[a-z0-9][a-z0-9-_]{1,63}$.
- GET /api/projects/:pid/environments -> {environments:[{id,key,name}]} (dev, staging, prod).
- GET /api/projects/:pid/flags?search=&tag=&limit= -> {flags:[{id,key,name,description,tags,isExperiment,goalMetricKey,environments:{[envKey]:{enabled,version}},updatedAt}]}.
- POST /api/projects/:pid/flags {key,name,description?,tags?,variations:[{key,name,value}],isExperiment?,goalMetricKey?,offVariation?,defaultVariation?} -> 201 {flag,sync}. 2 to 10 variations; variation key ^[a-z0-9][a-z0-9-_]{0,63}$; value is a string, number or boolean. New flags start disabled in every environment. 409 conflict if the key exists.
- GET /api/projects/:pid/flags/:key -> {flag:{id,key,name,description,tags,variations,isExperiment,goalMetricKey,environments:{[envKey]:{enabled,offVariation,fallthrough,rules,version}},createdAt,updatedAt}}.
- PUT /api/projects/:pid/flags/:key {name?,description?,tags?,variations?,isExperiment?,goalMetricKey?} -> {flag,sync}; 409 variation_in_use when removing a variation an environment still uses. An experiment needs goalMetricKey (^[a-z0-9][a-z0-9-_.]{1,63}$); a non-experiment must have none.
- DELETE /api/projects/:pid/flags/:key -> {deleted:true,sync} (admin).
- PUT /api/projects/:pid/flags/:key/environments/:envKey {enabled, offVariation, fallthrough, rules, expectedVersion?} -> {flag,sync}. fallthrough and every rule.serve are either {variation} or {rollout:[{variation,weight}]}; weights are integers that sum to exactly 100000 (so 1 percent is 1000), no duplicate variations. rules: [{id, conditions:[{attribute, operator, values}], serve}]; at most 50 rules, 10 conditions per rule, 100 values per condition; rule ids unique, ^[A-Za-z0-9_-]{1,64}$; at least one condition per rule. Operators: equals, notEquals, in, contains, startsWith, gt, lt. gt and lt take exactly one value (number or string); startsWith values are strings; values are string, number or boolean. Send expectedVersion (the version you loaded) and handle 409 version_conflict. Every variation key used must exist on the flag.
- POST /api/projects/:pid/flags/:key/environments/:envKey/evaluate-test {userContext:{key,...}} -> {variation,value,reason:{kind:"off"|"rule"|"fallthrough"|"error",ruleId?,errorKind?}}. Errors come back as a normal 200 (for example errorKind user_key_missing).
- GET /api/projects/:pid/flags/:key/results?env= -> {flagKey,env,goalMetricKey,control,alpha,variations:[{key,exposures,conversions,rate,vsControl:null|{lift,difference,ci95:[lo,hi],pValue,significant,sampleSizeOk}}]}; 400 not_an_experiment.
- GET /api/projects/:pid/environments/:envKey/sdk-keys -> {sdkKeys:[{id,prefix,type,createdAt,revokedAt}]} (editor). POST same path {type:"server"|"client"} -> 201 {sdkKey:{id,prefix,type,createdAt,revokedAt,key}}; the full key is returned ONCE (admin). DELETE .../sdk-keys/:id -> 204 (admin).
- GET /api/projects/:pid/audit?flag=&env=&before=&limit= -> {entries:[{id,action,flagKey,envKey,before,after,ts,actor:{id,name,email}}],nextBefore} (editor).
- Write responses include sync: "ok" or "delayed" ("delayed" means saved, but live updates may lag).
